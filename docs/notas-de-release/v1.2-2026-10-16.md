# Nota de release — versão 1.2 (16/10/2026)

Sistema de Controladoria Municipal · HorizonAJ

## Resumo

Os alertas passaram a ser **totalmente automáticos**. O controlador não precisa mais buscar informação no SICONFI, no RREO ou no RGF de outros sistemas, nem clicar em "Registrar alerta":

- a cada coleta, o sistema **cria, atualiza e encerra** os alertas sozinho;
- avisa o controlador e a equipe **por e-mail**;
- passou a trazer também **saúde, educação, FUNDEB, execução orçamentária e restos a pagar**.

## Novidades

### 1. Alertas criados automaticamente

- Cada irregularidade identificada no SICONFI vira um alerta numerado:
  - origem "Alerta automático";
  - selo **Automático** na lista;
  - histórico com o registro "criado automaticamente".
- **Atualização automática:** quando sai um novo demonstrativo ou a faixa piora (ex.: de alerta para prudencial), o alerta aberto recebe a nova descrição e a nova gravidade.
- **Encerramento automático:** quando a irregularidade deixa de constar (ex.: o demonstrativo foi entregue), o alerta é encerrado como "Resolvida", com justificativa automática. O plano de ação e o histórico ficam preservados.
- **Sem duplicidade:** existe no máximo um alerta aberto por indicador.
  - Se o controlador encerrar um alerta manualmente, ele não é recriado para o mesmo demonstrativo.
  - Ele só volta se a irregularidade persistir no período seguinte.
- **Câmara:** recebe alertas automáticos dos indicadores do próprio Poder (pessoal do Legislativo e entregas). Os indicadores do município (dívida, saúde, educação, meta fiscal) ficam visíveis para consulta, com registro manual opcional.

### 2. Aviso por e-mail

- O controlador e a equipe recebem um e-mail quando alertas são **criados** ou **encerrados**, com o número, a gravidade e o link de cada um.
- Atualizações de um alerta já aberto não geram e-mail, para evitar excesso de mensagens.

### 3. Coleta automática, sem depender de ninguém

- Além da rotina diária do servidor, abrir o Painel, Alertas ou Dados externos com dados de mais de 24 horas dispara a coleta em segundo plano.
- Depois de uma falha, o sistema espera 3 horas antes de tentar de novo, para não sobrecarregar as APIs públicas.

### 4. Novos indicadores (RREO, Anexo 14)

| Indicador | Alerta automático |
|---|---|
| **Educação (MDE)** — mínimo de 25% | "Abaixo do mínimo até o bimestre" até o 5º bimestre; "Mínimo descumprido" no 6º |
| **FUNDEB** — 70% na remuneração | idem |
| **Saúde (ASPS)** — mínimo de 15% | idem |
| **Meta de resultado primário** (LDO) | quando não é atingida no último bimestre |
| **Execução orçamentária** e **restos a pagar** | só consulta |

- **Dados externos:** dois blocos novos, "Saúde e educação — mínimos constitucionais" e "Execução orçamentária e restos a pagar".
- **Painel:** os índices em destaque incluem saúde, educação e FUNDEB.

## Banco de dados

- Migração `20261016120000_alertas_automaticos`. É aditiva e não perde dados:
  - `situacoes.criado_por_id` passa a aceitar nulo (alertas criados pelo sistema);
  - novas colunas `chave_automatica` e `referencia_automatica`;
  - índice único parcial (um alerta automático aberto por indicador);
  - CHECKs de integridade.
- Na implantação, rode `npm run db:deploy`.
- Na primeira coleta após a atualização, os alertas vigentes são criados de uma vez, e o controlador e a equipe recebem um e-mail.

## Implantação (VPS)

```bash
cd /opt/controladoria
git pull
docker compose -f docker-compose.prod.yml build app
docker compose -f docker-compose.prod.yml run --rm app npm run db:deploy
docker compose -f docker-compose.prod.yml up -d app
```

Recomendado: manter o cron diário `npm run integracoes:sincronizar`. A coleta ao abrir as telas é um complemento e não substitui a rotina do servidor.
